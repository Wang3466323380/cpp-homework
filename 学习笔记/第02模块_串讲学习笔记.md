## 01｜总路线：程序为什么离不开数据类型？

对应课件P1–2、P6。

把全章串成一条线：实际信息 → 用0/1编码 → 分配一定的存储位数 → 用类型解释这些位 → 用常量给出固定数据、用变量保存变化数据 → 按运算符构造表达式 → 在运算中转换类型 → 把结果赋回变量 → 输出给人看。

例如“输入两个数，求和”：键盘是输入设备，a和b接收输入，CPU进行加法，sum保存结果，屏幕是输出设备。类型决定a、b、sum能表示多大的数，也决定相除时是否保留小数。

冯·诺依曼型计算机包含运算器、控制器、存储器、输入设备、输出设备。CPU（Central Processing Unit）包含运算器和控制器；课件把存储器分为内存和外存。程序是一串指令；高级语言便于人编写，机器语言由CPU执行，编译与链接把C++源程序变成可执行程序。

数字、文本、图像、视频、声音最终都必须编码成0/1。同一串位可以按不同规则理解，因此“存了哪些位”与“这些位是什么意思”需要分开判断。

课件P2的课程地图：高级语言程序设计连接数据结构、算法分析与设计、编译原理、操作系统、计算机组成原理、数据库系统原理、大数据/数据仓库/数据挖掘、计算机网络、计算机安全，以及模式识别/机器学习/人工智能。当前先掌握程序和数据的基本规则。

## 02｜进制、位权与存储单位

对应课件P3–6。

N进制使用N种数码，数码值为0至N−1，逢N进一。N叫基数。个位、十位等位置有不同位权：整数部分从右向左为N⁰、N¹、N²……；小数点右侧依次为N⁻¹、N⁻²……。

课件原例：十进制使用0–9；24进制用0–23；60进制用0–59。215 = 2×10² + 1×10¹ + 5×10⁰。课件P3末项前的乘号应理解为加号。

二进制使用0、1。电路中的高低电平等两种状态容易实现和区分，所以计算机用二进制编码。bit（位）是一个二进制位；本课程环境中8 bit = 1 byte（字节）。b表示bit，B表示byte。

| 单位 | 课件采用的二进制递进关系 | 便于准确区分的写法 |
|---|---|---|
| KB、MB、GB | 每级乘1024，分别为2¹⁰、2²⁰、2³⁰字节 | KiB、MiB、GiB |
| TB、PB、EB | 分别为2⁴⁰、2⁵⁰、2⁶⁰字节 | TiB、PiB、EiB |
| ZB、YB | 分别为2⁷⁰、2⁸⁰字节 | ZiB、YiB |

准确理解：日常标注有歧义。KB/MB/GB也常按10³/10⁶/10⁹理解；用KiB/MiB/GiB能明确表示二进制倍数。课件P5还列出BB、NB、DB、CB及其2⁹⁰、2¹⁰⁰、2¹¹⁰、2¹²⁰递进，作为原表保留在HTML原页中；这些扩展名称不作为统一标准单位背诵。

课件原例逐一理解：

- 手机128GB与电视128Gb：相同倍数口径下，前者容量是后者的8倍，不能忽略大小写。
- 工资18K = 18000，K按1000理解。
- 宽带20Mbps = 20×10⁶ bit/s，理论上约2.5 MB/s；实际还会受到传输开销等影响。
- 笔记本内存8GB，课件按8×2³⁰字节理解。
- 厂商1TB硬盘按10¹²字节标注；换成TiB约0.9095。课件说“约9%误差”，更准确地说这是单位口径不同；容量本身没有因此丢失。

## 03｜进制转换：按权展开，除基取余

对应课件P7–9，补齐课件要求自学的小数转换与八/十六进制互转。

整数从十进制转N进制：反复除以N，记录余数，直到商为0，把余数倒序排列。反向转换：每一位乘相应位权，再求和。

课件原例：25÷2的商与余数依次为12余1、6余0、3余0、1余1、0余1。因此(25)₁₀=(11001)₂；反向算1×2⁴+1×2³+0×2²+0×2¹+1×2⁰=25。

八进制使用0–7；十六进制使用0–9、A–F（a–f同义），A至F依次表示10至15。

课件原例：

```text
(11418)₁₀ = (26232)₈ = (2C9A)₁₆
26232₈ = 2×8⁴ + 6×8³ + 2×8² + 3×8 + 2 = 11418
2C9A₁₆ = 2×16³ + 12×16² + 9×16 + 10 = 11418
```

除8的余数依次为2、3、2、6、2；除16的余数依次为10(A)、9、12(C)、2，均倒序读取。

二进制与八/十六进制转换更快：整数从最低位向左分组，每3位对应1位八进制，每4位对应1位十六进制；最左组不足时补0。反向把每位展开为3或4位。

```text
课件原例：1011100101011₂
按3位：1 | 011 | 100 | 101 | 011 → 13453₈
按4位：1 | 0111 | 0010 | 1011 → 172B₁₆
13453₈ → 001 011 100 101 011 → 1011100101011₂
172B₁₆ → 0001 0111 0010 1011 → 1011100101011₂
```

八与十六进制互转：以二进制为桥梁，例如13453₈ → 二进制 → 172B₁₆；不必先转十进制。

小数转换（补充）：十进制小数反复乘2，每次取整数位，保留小数部分继续，整数位按产生顺序排列。0.25×2=0.5取0；0.5×2=1.0取1，所以0.25₁₀=0.01₂。反向0.101₂=2⁻¹+2⁻³=0.625。整数和小数分别转换再合并；0.2这类数可能无限循环，不能指望有限位精确表示。小数二进制转八/十六进制从小数点向右分组，末尾补0。

## 04｜C++程序骨架：输入、处理、输出

对应课件P10–16。

课件原例1：

```cpp
#include <iostream>
using namespace std;
int main()
{
    cout << "Hello, World." << endl;
    return 0;
}
```

输出Hello, World.并换行。iostream提供输入输出声明；using namespace std让这里能直接写cin、cout、endl。main是主函数，程序从main开始；return 0表示正常结束。

课件原例2：

```cpp
#include <iostream>
using namespace std;
int main()
{
    int a,b,sum;
    cin >> a >> b;
    sum=a+b;
    cout << "a+b=" << sum << endl;
    return 0;
}
```

输入2 3会输出a+b=5。cin的两个整数可用空白分隔；提示文字与结果间的空格和符号必须自己写。

课件原例3：

```cpp
#include <iostream>
using namespace std;
int my_max(int x, int y)
{
    int z;
    if (x>y)
        z=x;
    else
        z=y;
    return z;
}
int main()
{
    int a,b,m;
    cin >> a >> b;
    m = my_max(a,b);
    cout << "max=" << m << '\n';
    return 0;
}
```

函数一般形式为“返回类型 函数名(形参表) { 函数体 }”。函数平行定义，可以相互调用；不能在普通函数体里再定义一个普通函数。my_max放在main后面时，需要在调用前提供声明，例如int my_max(int x,int y);。库函数与自己写的函数都通过函数调用使用。

一个程序可由多个.cpp源文件组成：各自编译为.obj，再链接成.exe。普通入门程序有一个main。课件前3章按单文件、单main学习，多函数/多文件在第4章展开。

语句与格式：声明、赋值、函数调用等通常以分号结束；花括号和if等结构不能机械地一律加分号。普通表达式跨行通常无需反斜杠。课件同时展示紧凑写法、带反斜杠换行与直接换行，含义相同，全部原写法见原页P13–14。

```cpp
// 课件的紧凑写法：语法可行，但不满足本课程一句一行的要求
int main() { cout << "Hello, World." << endl; return 0; }
// 普通表达式本来就能跨行
cout
    << "Hello, World."
    << endl;
```

注释：//直到本行末尾；/* ... */可以跨行。课件例中包括//命名空间、/* function main */、//Ausgabe(德文-输出)、/* fanhui :-) ^-^ */等，说明注释是给人读的。块注释不能直接嵌套。

课程要求与语言规则分开记：课件要求一句一行，违反格式规定该题扣10%；默认VS2026保持Debug/x64，小熊猫/gcc保持64-bit Debug，禁用auto。P16仅列安装、使用、编程步骤与作业格式的另发文档，没有给出安装细节。基本工作过程可理解为：编辑 → 编译 → 链接 → 运行 → 观察结果与调试。Debug便于调试，Release通常面向交付并开启更多优化；具体调试信息与优化受选项控制。x86/x64指目标程序平台，并不意味着所有变量都变为32/64位。

## 05｜有符号整数：从原码到补码

对应课件P17–22。

16位无符号整数范围为0至2¹⁶−1，即0–65535。若最高位用于正负号、后15位表示绝对值，这叫原码。额外再拿第17位存符号就不能放进原来的2字节，所以课件舍弃这种方案。

课件原例：原码00000000 00000001为+1；10000000 00000001为−1；01111111 11111111为+32767；11111111 11111111为−32767。原码存在+0与−0两种表示，并且直接按普通二进制加法计算−1+1会得到10000000 00000010（原码−2），不符合数学结果。

补码解决了这些问题。固定n位时：非负数直接写二进制并补齐位数；负数先写其绝对值的n位二进制，再逐位取反、加1。也可记作负数x的补码位模式对应无符号数2ⁿ+x。

| 课件原数值 | 16位补码 |
|---|---|
| 100 | 00000000 01100100 |
| −10 | 11111111 11110110 |
| 0 | 00000000 00000000 |
| −1 | 11111111 11111111 |
| −32768 | 10000000 00000000 |
| −32767 | 10000000 00000001 |

例：10为00000000 00001010，取反为11111111 11110101，加1得−10的补码11111111 11110110。−1+1得到1 00000000 00000000，保留16位得到0。零只有一个补码表示；原码中的−0位模式现在表示−32768。

| 同一16位模式 | 原码解读 | 补码解读 |
|---|---|---|
| 00000000 00000000 | +0 | 0 |
| 01111111 11111111 | +32767 | +32767 |
| 10000000 00000000 | −0 | −32768 |
| 10000000 00000001 | −1 | −32767 |
| 10000000 00000010 | −2 | −32766 |
| 11111111 11111101 | −32765 | −3 |
| 11111111 11111110 | −32766 | −2 |
| 11111111 11111111 | −32767 | −1 |

范围公式：n位无符号整数为0至2ⁿ−1；n位补码有符号整数为−2ⁿ⁻¹至2ⁿ⁻¹−1。负数比正数多一个值。−32768的正数绝对值32768不能作为16位有符号正整数表示，求其位模式时不要误说“16位有符号+32768的原码”。

课件P22原思考题：①“正数用原码、负数用补码”不准确：有符号整数统一用补码，正数补码恰好与原码相同。②最高位为1不能单独决定正负：还要知道位宽和signed/unsigned。同一个11111111，按8位unsigned为255，按8位补码signed为−1。

准确理解：课件用“逐字节相等”解释表示统一的好处，但不能推广为所有类型的相等判断，例如浮点数+0与−0位模式可不同却比较相等。

## 06｜类型决定字节数、范围和解释方式

对应课件P23–28、P31–32。

本章重点：整型short、int、long、long long，字符型char，浮点型float、double、long double，布尔型bool。课件还列出指针*、枚举enum、数组[]、结构体struct、共用体union、类class和空类型void。这是课程的分类导览；严格的标准分类中枚举等不直接归入“由基本类型构造的派生类型”。

| 课件环境的类型 | 字节 | 范围或说明 |
|---|---|---|
| signed char | 1 | −128至127 |
| unsigned char | 1 | 0至255 |
| short [int] | 2 | −32768至32767 |
| unsigned short [int] | 2 | 0至65535 |
| [signed] int | 4 | −2147483648至2147483647 |
| unsigned [int] | 4 | 0至4294967295 |
| long [int] | 4 | 与本环境int范围相同 |
| unsigned long [int] | 4 | 与本环境unsigned int范围相同 |
| long long [int] | 8 | −9223372036854775808至9223372036854775807 |
| unsigned long long [int] | 8 | 0至18446744073709551615 |
| float | 4 | 最大有限数约3.4×10³⁸，通常约6–7位十进制有效数字 |
| double | 8 | 最大有限数约1.7×10³⁰⁸，通常约15–16位十进制有效数字 |
| long double | 8 | 在课件VS模型中与double相同 |
| bool | 用sizeof核对；该模型通常1 | false或true，转为整数是0或1 |

浮点数的“范围”不是一整段可精确表示的实数：可表示值是离散的，还包括极小数；正负最大值不能说明最小正值和精度。[ ]表示可省略，例如signed int与int等价，long与long int等价。

跨平台只记大小关系：sizeof(short) ≤ sizeof(int) ≤ sizeof(long) ≤ sizeof(long long)，sizeof(char)=1；字节实际位数用CHAR_BIT确认。本课程假定CHAR_BIT=8。plain char是否有符号由实现决定，不能普遍说char一定等同signed char。课件比较的Turbo C、VS、Rocky Linux说明类型大小会随平台改变，64位Linux的long常为8字节，而Windows的long通常仍为4字节。

课件原例：十进制85=1010101₂；存为char时为01010101，short时前补8个0，int和课件long时前补24个0；类型占多少位就存满多少位。

课件工具例（完整测试列表与原程序见原页）：

```cpp
#include <iostream>
#include <climits>
#include <typeinfo>
using namespace std;
int main()
{
    cout << sizeof(int) << endl;                // 4
    cout << sizeof(unsigned int) << endl;       // 4
    cout << sizeof(long) << endl;               // 4
    cout << sizeof(unsigned short) << endl;     // 2
    cout << sizeof(unsigned long long) << endl; // 8
    cout << sizeof(float) << endl;              // 4
    cout << sizeof(long double) << endl;        // 8
    cout << INT_MIN << endl;
    cout << UINT_MAX << endl;
    cout << LLONG_MAX << endl;
    cout << SHRT_MAX << endl;
    cout << typeid(123L).name() << endl;
    return 0;
}
```

sizeof回答“多少字节”；typeid(...).name()用于观察类型，返回文本依实现而异。P32依次测试bool、char、unsigned char、signed short、unsigned short、int、unsigned、unsigned long、long long、unsigned long long、float、double、long double；VS常输出易读名称，gcc可能输出编码，不要背打印字符串。使用标准头文件，不依赖iostream间接包含climits、typeinfo。

课件P27/P54趣味题：不用LLONG_MAX怎么知道最大值？在已知64位模型下，cout << 0x7FFFFFFFFFFFFFFF << endl;；或unsigned long long x = -1LL; cout << x/2 << endl;。后者先把−1转为无符号最大值2⁶⁴−1，整数除2得2⁶³−1。可以用sizeof乘CHAR_BIT推导位宽，不能用有符号溢出“试出最大值”。

## 07｜数值常量：写法、类型、内部存储和输出要分开

对应课件P29–33、P37。

常量在程序运行过程中值不改变。字面常量直接写出数据；符号常量用名字代表。下面四种写法值相等：123、0b1111011、0173、0x7B，都是十进制123。二进制以0b开头；八进制以0开头；十六进制以0x或0X开头。0b102不是“另一种数字”，2不是合法二进制数码，应诊断。二进制字面量从C++14开始进入标准。

课件原排序题：0x123=291，123=123，0123=83，所以0x123 > 123 > 0123。前导0会改变含义，不能随意补零。

课件P30三个输出原例可压缩为：

```cpp
cout << 119 << endl;
cout << 0b1110111 << endl;
cout << 0167 << endl;
cout << 0x77 << endl;
// 四行都输出119（流原先使用十进制时）

cout << hex << 119 << endl;
cout << hex << 0b1110111 << endl;
cout << hex << 0167 << endl;
cout << hex << 0x77 << endl;
// 四行都输出77

cout << dec << 119 << endl;                      // 119
cout << "0x" << hex << 0b1110111 << endl;         // 0x77
cout << "(" << oct << 0167 << ")8" << endl;      // (167)8
```

数值在源程序中的进制写法，不决定输出进制。hex、oct、dec改变流的后续整数输出状态，状态会保留，必要时恢复dec。默认不会自动加0x或下标，原例手动加了修饰；也可了解showbase。标准iostream没有与hex对应的通用bin操纵符，二进制显示可在后续用bitset等实现。

| 课件原字面量 | 类型 |
|---|---|
| 123 | int |
| 123L | long |
| 123U | unsigned int |
| 123UL、123LU | unsigned long |
| 1.23 | double |
| 1.23F | float |

大写L更不容易与数字1混淆。还有LL/ULL表示long long/unsigned long long；没有专门的short字面量后缀。“整数字面量默认int”只适用于值能装入相应候选类型的情况；较大字面量会按进制、后缀和可表示范围选择类型。

课件原浮点常量：0.123、123.456、123.0；指数写法123e4、12.3e5、1.23E6、0.123e7、0.0123e8都为1230000。e前须有数，e后须有整数指数；1.23e4、1.23E-4、-1.23e-4合法；e4、1.23e4.5不合法。负号在语法上是作用于字面量的运算符。

准确理解：课件只教十进制浮点字面量；现代C++还支持十六进制浮点字面量，不要把“只有十进制”当成语言完整规则。P37的sizeof(1.23)、typeid(1.23).name()、sizeof(1.23F)、typeid(1.23F).name()在课件环境下分别说明8字节double与4字节float。

## 08｜浮点数：范围很大，精度有限

对应课件P34–37、P59、P130。

整数用固定数量的位存整数值，浮点数把位分给符号、指数和尾数，所以能覆盖更大的数量级，但不能精确表示每个小数。常见IEEE 754 binary32（float）为1位符号、8位指数、23位小数部分；binary64（double）为1、11、52位。

正规格化有限非零值的理解公式：值 = (−1)^符号 × (1+小数部分) × 2^(指数域−偏置)。float偏置127，double偏置1023。隐含的前导1为精度多贡献一位；零、次正规数、无穷和NaN有专门规则，不能直接套这个公式。

课件原例100.25：

```text
100 = 1100100₂；0.25 = 0.01₂
100.25 = 1100100.01₂ = 1.10010001₂ × 2⁶
符号：0
指数域：6+127=133=10000101₂
尾数域：10010001000000000000000
32位模式：0x42C88000
```

尾数小数为2⁻¹+2⁻⁴+2⁻⁸=0.56640625，所以1.56640625×2⁶=100.25，可精确表示。课件还用十进制1230000的12.3e5、1.23e6、0.123e7、0.0123e8，对照二进制101101的10.1101×2⁴、1.01101×2⁵、0.101101×2⁶、0.0101101×2⁷，说明同一个数可以用不同指数写法，而二进制规范形式要求前导1。

课件原例−1.2：0.2连续乘2取整产生0011循环，所以其绝对值是1.001100110011……₂。float只能保存有限位并舍入，结果位模式为0xBF99999A；符号1，指数域01111111表示实际指数0，小数域00110011001100110011010。实际保存值约−1.2000000476837158203125，绝对值略大于1.2，数值本身更负。不能简单说“−1.2的值略大”。

课件用于查看4个字节的原程序核心：

```cpp
float f = 100.25; // 换为-1.2即另一原例
unsigned char* p = (unsigned char*)&f;
cout << hex << (int)(*p) << endl;
cout << hex << (int)(*(p+1)) << endl;
cout << hex << (int)(*(p+2)) << endl;
cout << hex << (int)(*(p+3)) << endl;
```

指针部分后续章节才学，这里当观察工具。Windows常见小端布局中，从低地址依次打印100.25的字节为00、80、c8、42；−1.2则为9a、99、99、bf。课件按高位到低位列42 c8 80 00与bf 99 99 9a，需区分位模式书写顺序和地址中的字节顺序。程序未用补零格式时，00会显示为0。

课件原例：double d=1.23456e38; float f1=d; float f2=d*10;。f1在float有限范围内但可能舍入；f2超float最大有限值，在课件VS环境下观察到inf。警告数量和越界转换行为依编译器与选项，不作为可移植结果使用。

float转double能精确保留原先float已经存下的有限值，不能恢复之前丢失的精度；double转float可能舍入或越界。整数转浮点也可能失去精度：课件中的char 123→float、int 12345→double可精确；long 1234567、123456700、123456789转float的输出分别可能显示1.23457e+06、1.23457e+08、1.23457e+08。默认输出位数少与内部舍入是两件事，打印得一样不代表内部值相等。

有效数字是整体精度，不是“小数点后位数”。课件将float/double概括为6位/15位，适合先记近似量级；实际以二进制有效位和舍入规则决定，并非固定截掉第7/16位十进制数字。

## 09｜字符与转义：字符也是有编码的整数

对应课件P38–42、P60–63。

ASCII是American Standard Code for Information Interchange。准确的基本ASCII为7位、128个编码；常用一个8位字节存放。“扩展ASCII”是多种8位编码的俗称，并非单一统一的256字符ASCII标准。0–31和127是控制码；空格32应单独理解，33–126为可见图形字符。课件把空格纳入“控制字符”是其教学口径。

必须记：'0'=48=0x30，空格=32=0x20，'A'=65=0x41，'a'=97=0x61。这里按ASCII兼容环境解释。

课件汉字编码介绍：GB2312、GBK、GB18030不断扩展可表示字符，汉字通常需要多个字节；课件列有GB2312的6733、GBK的20000+、GB18030的70000+等规模说明，原表述保留在P38原页。这些是课件中的概括，不据此推定每种编码的精确收录数或版本。一个字符占几个字节必须先确定编码，不能把“一个汉字两个字节”推广到所有场景。

普通字符用单引号，例如'A'、' '。引号表示边界，若字符本身是引号或反斜杠，就要使用转义。'''、'''''不是表示单引号的正确办法。

| 含义 | 写法与课件原例 |
|---|---|
| 普通n与换行不同 | 'n'是字母，'\n'是换行 |
| 反斜杠 | '\\' |
| 单引号 | '\'' |
| 双引号 | '\"'，也可用'\42'、'\042'、'\x22' |
| A | 'A'、'\101'、'\x41' |
| 换行（编码10） | '\n'、'\12'、'\012'、'\xA'、'\x0A'、'\xa'、'\x0a' |
| ESC（编码27） | '\33'、'\033'、'\x1b'、'\x1B' |
| 数字字符0（编码48） | '0'、'\60'、'\060'、'\x30' |
| 零字符（编码0） | '\0'、'\00'、'\000'、'\x0'、'\x00' |

常用转义补充：\t为水平制表，\r为回车，\b为退格，\a为响铃，\f为换页，\v为垂直制表。显示效果受终端影响。

八进制转义：反斜杠后最多取3个八进制数字；在8位字节的例中，\000至\377覆盖0–255。十六进制转义以小写x开始，后面的A–F大小写均可。注意整数字面量0X41中的X可以大写，但转义中的\X41不是合法的十六进制转义。

准确理解：\x后并非语法上“最多两位”，它会继续吞入后续十六进制数字。若数值不能由目标字符类型允许的范围表示，会出现诊断。两位足够表示一个8位字节，不等于解析时只读两位。

课件原测试：cout << '\377';、cout << '\477';、cout << '\x41';、cout << '\X41';。第一项是数值255的字符，显示依编码而异；第二项八进制477=319超出8位范围；第三项输出A；第四项含无效转义，不当作十六进制65理解。具体是error还是warning、几条诊断，依编译器和选项。

课件原观察程序：cout << 'A' << endl;、sizeof('A')、typeid('A').name()、int('A')，对应A、1、char类型名称、65。这里是C++；C语言普通字符常量的类型规则不同。'汉'这类多字节内容不能当普通单字节char可移植地使用，P42把它作为编译器差异反例，而不是推荐写法。

课件P61–62成对原例：把65、0b1000001、0101、0x41、0X41分别赋给char a,b,c,d,e，均保存编码65，cout分别显示A；将变量改成int，分别显示65。把'A'、'\101'、'\x41'赋给char或int，结论相同，但右侧字面量类型不同。

```cpp
// 课件P63：仅在ASCII小写字母范围内使用此规律
char c1,c2;
c1 = 'a';
c2 = 'b';
c1 = c1-32;
c2 = c2-32;
cout << c1 << ' ' << c2 << endl; // A B
```

字符先提升为int计算，再转回char保存。若c1、c2改为int，输出65 66。不能对任意字符一律减32来转换大小写。

## 10｜字符串：字符序列末尾还有一个零

对应课件P43–45、P64。

字符串字面量用双引号，例如"abc"。普通字符串字面量是包含尾零的const char数组；"abc"在内存中是'a'、'b'、'c'、'\0'。课件用ASCII码逐字节说明其存储。

课件P44对比两种不定长序列设计：①前面记录长度，如1字节长度字段最多记录255，2字节最多65535；②末尾放结束标志。C风格字符串采用尾零方案，strlen从开头数到首个零，不计尾零。

| 课件原例 | strlen得到的长度 | sizeof得到的字节数 |
|---|---|---|
| "" | 0 | 1 |
| " " | 1 | 2 |
| "A" | 1 | 2 |
| 'A' | 不能传给strlen | 1 |
| "Hello\0ABC" | 5 | 10 |

strlen('A')在课件8行测试中是编译错误：strlen需要指向字符序列的指针，不是一个字符。sizeof计算对象或类型所占字节；对于这里直接写出的字符串字面量，它包括自动附加的尾零。strlen运行时找第一个零，所以遇到中间零会提前结束。准确理解：字符串字面量可以含内嵌零；不能把课件“\0不是合法字符”理解为语法禁止出现\0。

使用strlen需包含<cstring>，更规范地写std::strlen。普通窄字符串下它数的是字节，不是用户感知的汉字数。课件的"中"和"同济"在常见GBK执行编码下sizeof分别为3、5，在UTF-8下常为4、7；因此先明确执行字符编码，再讨论结果。

课件原复杂转义例：

```cpp
strlen("abc123*#")                           // 8
strlen("\x61\x62\x63\061\62\063\x2a\043") // 8
strlen("\r\n\t\\A\\t\x1b\"\1234\xft\x2f\33") // 15
// 原课件还列含\9234的版本，用于观察非法转义的诊断
```

第三串逐项拆为：\r、\n、\t、反斜杠、A、反斜杠、t、ESC、双引号、\123、4、\xf、t、\x2f、\33，共15个字节。\1234只吞3位八进制数字，留下字符4；\xft在f后遇到非十六进制t，成为一个值15的字符和t。

课件原诊断对比："\1234"长度2；"\x2fa"把2fa全部当十六进制数，超出8位字符范围；"\9234"和"\*123"包含不受普通规则支持的转义，课件编译器可能警告后继续，不能背为标准字符串结果；"\xg123"、"\x*123"在x后没有合法十六进制数字，应诊断。若要写值0x2f再接字母a，可以用相邻字面量"\x2f" "a"分开。

准确理解：课件P64“C++中无字符串变量”应理解为“没有内建的基本字符串类型”；C++标准库提供std::string，本课暂用一维字符数组学习C风格字符串，后续再展开。

## 11｜变量、初始化、宏与const

对应课件P46–51、P65–66。

变量是有名字、类型、存储空间和值的对象；程序可以改变其值。int a;意味着名字a、类型int、课件环境下4字节、约±21亿的整数范围，以及一个运行时地址。&a表示起始地址。

课件原地址例：a从0x000000C25754F4D4开始占4字节，覆盖到……F4D7；此地址仅为一次运行示例，不能背为固定位置。课件x64下地址用64位模型，x86用32位模型，均不改变int通常占4字节这一点。

标识符的入门规则：字母或下划线开头，后接字母、数字、下划线，区分大小写，不能与int、float等关键字同名。课件合理例A、a、a1、_a、_a1、a1_b、abc；不合理例1a、a-b、int float;。cnol（字母l）与cno1（数字1）是不同名字，先定义再使用能帮助发现拼写错误。同一作用域不能重复定义同一个变量；按含义命名更容易读。

准确理解：标识符不是统一限制32字符；中文等Unicode标识符的支持与标准、编码和编译器设置有关。课程建议用简单英文名。带双下划线等名字有保留规则，初学者避开系统式命名即可。

课件定义例：int a; unsigned int b,c; long e,f; short i,j; float f1,f2; double d1,d2; char c1;。定义时可以初始化：

```cpp
int a=10;
char b='B';
int x=10, y=15*2, z=30;
int p=10, q=p, r=q+1; // 10、10、11
```

int a=b=c=10;若b、c未声明就错误，它只声明a，不会顺带声明b和c。课件反例与对照：int c,b,a=b=c=10;正确，因为先声明c、b，再把10依次赋给它们并初始化a；但清晰写法仍是int a=10,b=10,c=10;或先int a,b,c;再a=b=c=10;。

课件未初始化反例：int k; cout << k << endl; k=10;。局部普通int没有自动得到可用初值，先读取再赋值错误。编译器可能报错、警告或表现为某个值，不能把它解释为“总会得到随机数”，也不能靠某次运行似乎为0证明安全。

课件auto观察例：auto x=12;、auto y=1.2F;、auto z=1.2;分别推导为int、float、double，课件环境sizeof依次4、4、8。它是C++合法特性；本课程禁用是教学要求，做作业遵守即可。

符号常量：#define pi 3.14159。宏是预处理记号替换，不是一个有类型的变量；在10000处使用π时，修改定义可统一降低至3.14或提高至3.1415926。课件用“喵喵”替换int、“喵喵喵”替换main等宏拼出程序，最后输出“喵喵喵!”；完整宏映射与原代码保留在HTML原页P46。这一趣味例用于理解替换，不用于正常命名。

const常变量：const int a=10;或int const a=10;，这个普通局部常量对象必须初始化，之后不能写a=15;。课件P65的double pi=3.14159;本身不是常变量，要加const才成立。

课件P66两种圆面积/球体积写法：

```cpp
// 方案一：在函数外写 #define pi 3.14159（不带分号）
// 方案二：在函数中写 const double pi=3.14159;（带分号）
double r=3, s, v;
s = pi*r*r;
v = pi*r*r*r*4/3;
cout << s << endl;
cout << v << endl;
// 默认精度常显示28.2743、113.097
```

const具有类型和对象语义，宏是替换；此场景推荐const。漏掉const定义的分号会把下一行粘进语法分析，改后面乘法顺序不能修复它。若宏错误写成#define pi 3.14159;，则s=pi*r*r;展开为s=3.14159;*r*r;，语法错误。

课件的宏分号思考继续：s=r*r*pi;展开为s=r*r*3.14159;;，可能意外编译通过；v=r*r*r*4/3*pi;也能编译，但一般可能先发生整数除法，需看r的类型，本例r为double所以保留小数。把调用处末尾分号省去，宏内的分号又可能恰好补上，但这种依赖宏带分号的写法非常脆弱。正确做法是宏值不带分号、语句自己带分号，或改const。

## 12｜整数转换：同一组位，不同解释

对应课件P52–58、P131。

分析转换先问：源值是什么？源类型的位宽与signed/unsigned是什么？目标类型能否表示原值？最后再算目标值。值在目标范围内时通常保持原值；课件用符号扩展、补0、保留低位解释常见机器表现。

以下是课件全部成组数值原例。signed目标越界转换的结果按课件环境列出；C++20以前相关规则有实现定义部分，现代规则也不能与“有符号算术溢出”混为一谈。

| 课件页 | 源类型与值 | 目标或操作 | 课件模型结果 |
|---|---|---|---|

## 13｜算术与类型提升：每一步都要判断类型

对应课件P67–70、P119–122、P126–130。

运算符按操作数个数分一元、二元、三元。条件运算符写成?:，并非课件P67写出的倒序“:?”。+ − * / %是本块重点；%为整数余数，不是乘方，课件明确勘误教材把%印成^的问题。

| 本章主要运算符 | 结合方向 | 相对优先级 |
|---|---|---|
| 后缀++、-- | 左 | 高 |
| 前缀++、--，一元+、−，C式强转 | 右 | 其次 |
| *、/、% | 左 | 高于加减 |
| 二元+、− | 左 | 高于赋值 |
| =、+=、−=、*=、/=、%= | 右 | 低 |
| 逗号运算符 | 左 | 最低 |

括号可以明确分组。课件附录编号采用后缀第2组、前缀第3组、乘除余第5组、加减第6组、条件第15组、赋值第16组、逗号最低；不同资料分组编号可能不同，真正要记运算符间的关系。未提供的附录D不能据此补出完整18组原表。

整数除法向0截断：10/3=3，−10/3=−3。余数满足a=(a/b)*b+a%b；除不尽时余数与左操作数a同号。除数不能为0；还需排除最小有符号数除以−1这种结果超范围的情形。

课件P68余数原例完整保留：

| a与b的绝对值 | 正%正 | 正%负 | 负%正 | 负%负 |
|---|---|---|---|---|
| 10与3 | 10%3=1 | 10%−3=1 | −10%3=−1 | −10%−3=−1 |
| 10与7 | 10%7=3 | 10%−7=3 | −10%7=−3 | −10%−7=−3 |
| 7与3 | 7%3=1 | 7%−3=1 | −7%3=−1 | −7%−3=−1 |
| 3与7 | 3%7=3 | 3%−7=3 | −3%7=−3 | −3%−7=−3 |

字符参与算术前提升，课件原例'A'*10 → 65*10 → 650，结果为int。%两边须为整数类型，不能写5.5%2。

课件原陷阱（P68使用double pi，P121改成float pi，结论相同）：


后面出现double不会“回头修复”先前已经做完的整数除法。

混合运算逐个运算符转换：本课程环境char、signed/unsigned char、short、unsigned short先提升到int；若有浮点操作数，另一边转到合适的浮点类型。float与int运算结果通常仍是float，不能一概说先转double。两边都是整数时，先提升，再按等级、符号和可表示范围确定共同类型。

课件原逐步类型：'a'+10+15L+1.2依次为int、long、double；不是一开始把全部数据都转double。short a=1,b=32767; cout << a+b;输出32768；sizeof(a+'A')为4，typeid(a+b)观察到int，验证整型提升。

课件的long double > double > float > unsigned long long > long long > unsigned long > long > unsigned int > int是入门简表，P122已注明并非完全正确。精确处理signed/unsigned混算：无符号类型等级不低于有符号类型时用无符号；若有符号等级更高且能表示无符号全部值则用有符号，否则用该有符号类型对应的无符号类型。课件int a=2; unsigned int b=3; a-b结果是4294967295；若b也为int则为−1。

课件原式10+'a'+1.5-8765.1234*'b'中，'a'和'b'先按ASCII解释；乘法产生double，左侧10+'a'先为int，再与1.5组成double，最后相减为double。若按ASCII a=97、b=98，数学值为−858873.5932，实际浮点结果有舍入，默认cout可能采用科学记数法。

强制转换三种原形式：(int)(a+b)、int(a+b)、static_cast<int>(a+b)；单个a也一样。转换产生结果，原变量类型和值不因单独转换而改变。

## 14｜两个栈看懂复杂表达式

对应课件P70–118、P121。

栈是后进先出（LIFO，Last In First Out）。课件用“运算数栈+运算符栈”演示表达式的分组与计算依赖，避免只凭“先乘除后加减”跳步。这里只是手算/解析模型，不要求编译器运行时真的建立这两个栈。

扫描规则：读到运算数就进数栈；读到运算符，如果栈顶优先级更高，或相同且来者左结合，就先把栈顶运算符及两个操作数弹出计算，再把结果入栈，重复比较；否则运算符进栈。运算时先弹出的数是右操作数，后弹出的数是左操作数，减法和除法不能反。左括号进栈作为屏障；遇右括号，计算至对应左括号，然后移除这一对括号。结束后清空运算符栈，数栈剩一个结果。

课件原例1：10+'a'+i*f-d/e。变量类型i:int、f:float、d:double、e:long。完整分组为((10+'a')+(i*f))-(d/e)。

| 关键扫描点 | 数栈（左为栈底） | 符号栈 | 原因 |
|---|---|---|---|
| 读完10+'a' | 10, 'a' | + | 等待后继符号 |
| 遇下一个+ | A=10+'a' | + | 同级左结合，先合并前一项 |
| 读入i*f | A, i, f | +, * | *高于+，暂时压入 |
| 遇− | B=A+(i*f) | − | 先归约*，再归约+ |
| 读入d/e | B, d, e | −, / | /高于− |
| 扫描结束 | B−(d/e) | 空 | 先归约/，再归约− |

课件的5个求值步骤：①10+'a'为int；②i*f为float；③①+②为float；④d/e为double；⑤③−④为double。P72–92每个进栈/归约画面均在HTML原页保留。

课件原例2：10+('a'+i)*(f-d)/e。完整分组为10+((('a'+i)*(f-d))/e)。

| 关键点 | 合并得到 | 类型 |
|---|---|---|
| 第一个右括号 | A='a'+i | int |
| 第二个右括号 | B=f-d | double |
| 遇/时归约前面的* | C=A*B | double |
| 扫描结束先归约/ | D=C/e | double |
| 最后归约+ | 10+D | double |

第一个左括号进入时，之前的+不能越过它合并；第二个左括号保护f-d。P93–118完整展示进栈、移除括号、归约乘除与最后求和，HTML保留全部中间帧。

补充数值例：令i=2、f=3.0F、d=8.0、e=2L。例1为107+6−4=109.0；例2为10+99×(−5)/2=−237.5。只是补充赋值，原课件没有为这四个变量指定数值。

准确理解：优先级与结合性决定“怎么分组”，通常不规定独立子表达式谁先在机器上执行。这里按课件顺序手算便于理解，不推出“C++所有运算都从左到右实际执行”。P70的a+b、a*b+c、a+b+c、a+b*c、a+b*c-d、a+b*c*d及a+=a-=a*a，可用同一分组规则分析；出现副作用时还必须考虑求值顺序规则。

## 15｜自增、赋值与副作用

对应课件P123–137。

前缀++i：改变i，表达式使用新值；后缀i++：表达式产生旧值，同时使i增加1。--同理。单独作为语句时，i++;与++i;对普通整数最终效果相同。

课件原例：int i=3,j; j=++i;后i=4、j=4；重新从i=3开始，j=i++;后i=4、j=3。它们不是依次接着运行的同一个初始状态。前缀优先级低于后缀，但二者都高于赋值。

课件效率思考：后缀语义需要保留旧值，前缀不需产生旧值结果；不过普通整数单独自增时通常可优化成相同指令，不能断言前缀始终更快。该区别在复杂类类型中可能更有意义。

必须作用于可修改对象。课件反例(i+j)++、10++、const int k=3; k++;都不合法。课件原例int i=3,k; k=(i++)+(i++)+(i++);是未定义行为，不能靠一次VS/gcc运行结果规定答案。普通加法两侧没有把这些修改按顺序排好。

赋值表达式不仅修改对象，也产生结果。课件原例a=b、a=15、a=b*c-d、a=(b=5)；右侧完成后，结果转换成左侧目标类型并存入左侧。左边更准确的条件是“可修改左值”，不限于直接写一个变量名。

赋值右结合：a=b=c=5解释为a=(b=(c=5))。变量已定义时，依次让c、b、a为5；若左侧类型不同，每层存储转换可能改变后续传递值，不应一概认为永远传播原始右侧数值。

复合赋值共有10种：+=、-=、*=、/=、%=以及位运算的<<=、>>=、&=、^=、|=；本章重点前5种。它们在赋值这一层同级右结合。课件a+=b近似a=a+b；a*=b+1近似a=a*(b+1)，别漏右侧括号。一般情形复合赋值左操作数只求值一次，不能机械展开复杂左侧。

课件原重点：

```cpp
int a=12;
a += a -= a*a;
cout << a << endl;
```

按C++17及之后内建赋值的求值顺序规则：分组a += (a -= (a*a))。a*a=144；内层把a改为12−144=−132；再外层把当前a与内层结果相加，得到−264。较早标准对这类同一对象的修改/读取有不同限制，因此要标明语言版本，不仅看VS/gcc品牌。学习时推荐拆为清晰语句，练习分组则保留原式。

课件P136原对照：(a=3*5)=4*3;合法，赋值结果是指向a的左值，最终a=12。a=3*5=4*3;按右结合等同a=((3*5)=(4*3));，中间试图给临时乘积15赋值，非法。这里也说明“赋值左侧必须是变量名”是过度简化。

课件P137：cout << (a=10)+(a=20) << endl;也是对同一对象的无顺序修改，属于未定义行为。原页列出40、30等编译器观察值，保留作反例，不能列为合法的多个可选答案。正确需要的顺序请明确拆开语句。

## 16｜逗号表达式与全章解题流程

对应课件P138–139。

内建逗号运算符按从左到右完成各表达式求值，整体结果取最后一个表达式，优先级最低。与普通+不同，逗号运算符保证左侧完成后再执行右侧。

课件全部原例：

| 原式 | 执行后的a | 表达式结果或b |
|---|---|---|
| a=3*5, a*4 | 15 | 整体60 |
| (a=3*5, a*4), a+5 | 15 | 整体20 |
| b=(a=3*5, a*4) | 15 | b=60 |
| b=((a=3*5, a*4), a+5) | 15 | b=20 |

课件int a=5,b=4,c=3; cout << a << b << c; cout << (a,b) << (a,c) << (a,b,c);连续输出543433。第一条输出543，第二条输出433，因为各括号内分别取b、c、c。没有空格或换行，输出会直接连在一起。

注意：int a=5,b=4,c=3;中的逗号是声明分隔符；函数调用f(a,b)中的逗号是实参分隔符，均不能直接套用“最后一个决定值”的逗号运算符规则。

课件P139原对照：b=(a=3*5,a*4)最外层是赋值表达式，b=60；b=a=3*5,a*4最外层是逗号表达式，先使a和b为15，再算a*4=60，整体为60但b仍为15。“最后一个运算”应理解为完整分组后的最外层运算，不能只看最右边的符号。

全章统一做题流程：

1. 列出变量类型、位宽、初值；明确课件平台和标准版本。
2. 检查字面量的进制、后缀与转义，写出真正数值。
3. 按括号、优先级和结合性确定分组。
4. 检查是否存在未初始化读取、越界或未定义行为；有则不能硬算固定答案。
5. 每完成一个运算，先做整型提升或共同类型转换，再计算结果。
6. 赋值时再转成左侧类型，记录变量新值；区分表达式结果与变量最终值。
7. 输出时检查char/整数类型、hex/oct/dec状态、空格换行和输出精度。

课件说“任意类型表达式均有值”，对本章算术、赋值、逗号表达式可据此练习，但完整C++还存在void表达式等，不能无限推广。

1. 0123是八进制，值83，int；0x41值65，int；'\101'是A，char；"A"是包含A与尾零的const char[2]字面量；1.2F是float近似值。
2. 11111111 11110110；转unsigned short为65526，转32位unsigned int为4294967286，分别是2¹⁶−10与2³²−10。
3. x=3.0、y=3.5、z=3.0；z在转换前已经完成整数除法，无法补回0.5。
4. x=32768；t在课件模型为−32768。两处加法都先在int里做，差异在赋值目标转换。
5. 'a'+i为99/int；f-d为−5.0/double；乘积−495.0/double；除e得−247.5/double；加10得−237.5/double。
6. 第一种先a++使a=6，再a*2得到12赋b，所以a=6、b=12。第二种等同(b=a++),a*2，b先取得旧值5，a变6，整体逗号表达式结果12但不赋回b，故b=5。
7. 4、1、1；strlen接收字符序列指针，单个char不是字符串。
8. 参考程序：

```cpp
#include <iostream>
using namespace std;
int main()
{
    const double pi=3.14159;
    double r,h;
```

## 易错点速查

| 看到的写法或说法 | 立即检查什么 |
|---|---|
| 0123 | 前导0意味着八进制 |
| 1/3*pi | 1/3是否先做了整数除法 |
| char输出“不是数字” | cout按char显示字符；需要时转int |
| '0'、0、'\0' | 编码48的字符、int零、编码0的字符 |
| "A"与'A' | 字符数组含尾零；单个char |
| sizeof与strlen | 对象字节数；到首个零的长度 |
| char/short相加 | 先提升，不一定在原窄类型计算 |
| float转double | 保留已有近似，不恢复丢失精度 |
| unsigned与负数混算 | 先求共同类型，结果可能是大正数 |
| 有符号溢出 | 不靠补码回绕猜合法结果 |
| 多个++或赋值放进+ | 检查无顺序副作用，可能未定义行为 |
| 宏定义结尾分号 | 它会被替换进使用处 |
| a*=b+1 | 右侧整体是b+1 |
| b=(...),... | 先看逗号和赋值的完整分组 |
